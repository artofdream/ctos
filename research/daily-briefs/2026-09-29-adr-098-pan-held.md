# 2026-09-29 — ADR-098: PAN held while the kernel handles EL0 exceptions (correction)

- **Ask:** DSO relay (2026-09-28 23:54 CEST): split the PAN fix found in ADR-097 (#150) into its own PR on `main`, because the accepted ADR-091 clause “PAN is enabled” is false on `main` while the kernel handles EL0 exceptions. It should merge without waiting for #150's rev 4 accept.
- **Defect ([ADR-098](../../docs/03-adr/ADR-098-pan-held-during-el0-exceptions.md)):** `SCTLR_EL1.SPAN` was 1, so every exception from EL0 entered EL1 with PAN clear; `return_from_el0` resumed the kernel with SPSR.PAN clear, so PAN stayed clear after EL0 trips until the next copy helper. The ADR-080 boot probe runs before any EL0 trip and never saw it. From the ADR-080 enable, and from the M6 accept, until this fix the clause held at boot but not while handling EL0 exceptions.
- **Fix:** SPAN=0 after a successful enable; SPSR.PAN on `return_from_el0`.
- **Probes (fail-closed):** `pan: live-syscall pstate-pan=1 sctlr-span=0` (inside the loaded app's `SYS_YIELD` handler), `pan: after-el0 trips=<n> mrs-pan=1 el1-load va=0x80003000 fault=yes spsr-pan=1` (after the app exits), `pan: ok held boot,live-syscall,after-el0`. The negative build `pan-keep-leak-probe` (in the `el0-leak-probe` smoke kernel) undoes the fix: the boot probe still passes, and the smoke requires `pan: lost live-syscall …` / `pan: lost after-el0 …` and no `pan: ok held`.
- **Probed this session:** full `./scripts/qemu-smoke.sh` on the box (QEMU 10.0.13 TCG): `qemu-smoke: ok`, 149 tests including `pan_span_cleared_after_enable`, negative build caught. Tampered-log tests 7/7 fail, unedited passes. CI ids are in the PR and ledger.
- **Not claimed:** anything beyond the ADR-091 sentence (unchanged, now literally true again); real hardware; multi-core; every exception type sampled.
