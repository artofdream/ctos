# 2026-10-19 — ADR-104: SMP slice S4

- **Sponsor "Go on S4"**, relayed by DSO on 2026-10-19 at 17:31 CEST; the stop-all hold is lifted for this item only.
- **PerCpu via `TPIDR_EL1`:** one block per core (saved kernel TTBR0 at offset 0, id, ASID generation seen); the four lower-EL trampolines load TTBR0 through it. 71 EL0-context / expected-fault statics are banked per core. Core 0 installs its block only after the identity tears (the ADR-037 rewrite would corrupt the saved TTBR0).
- **ASID allocator:** 3..=255, `(generation, asid)`, spin lock; rollover = generation + 1, running ASIDs kept reserved, `tlbi vmalle1is`. Opt-in build only.
- **Core 1 in kernel mode:** kernel vectors, own SP_EL1 / SP_EL0, SPSel=0, own GIC CPU interface + timer. All 13 EL0 isolation probes pass on core 1 (`smp: cpu1 probe <name> ok cpu=1`). Both cores allocate 300 ASIDs concurrently across a rollover with no duplicates; a reissued ASID faults on core 1 after core 0's broadcast rollover.
- **Negatives:** one S4 leak build (all existing leak features + `asid-rollover-local-probe`): every leak caught on core 1, `smp: asidgen leak`. 20/20 on the box (QEMU 10.0.13); S3 xtlb leak 20/20 too.
- **Not claimed:** SMP safety; concurrent EL0 on both cores; ASID tagging under TCG (QEMU flushes on ASID change). ADR-091 rev 4 stays one core.
