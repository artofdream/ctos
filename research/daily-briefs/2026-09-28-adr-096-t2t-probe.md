# 2026-09-28 — ADR-096: task-to-task EL0 isolation probe

- **Ask:** milestone 1 (sponsor-approved 2026-09-28 21:21 CEST, relayed by the DSO): prove one EL0 task cannot read (or write) another EL0 task's memory. One branch, one PR; DSO/sponsor merge (ADR-002).
- **Probe ([ADR-096](../../docs/03-adr/ADR-096-task-to-task-el0-isolation-probe.md)):** task B runs on the ASID-B TTBR0 (ASID 2) and writes sentinel `0x7a5cb0b0` to its private page at `0x80007000`. Task A runs on the user TTBR0 (ASID 1) straight after, with no TLBI of that VA. A's load and A's store both take a lower-EL translation fault at that VA (`t2t: a-read fault …`, `t2t: a-write fault … b-intact=true`), and A never sees the sentinel. A walk shows A's root has no leaf for B's frame. Round 2 maps A's own frame at the same VA, and each task reads and writes only its own frame (`t2t: same-va …`). The run ends with `t2t: ok asid-a=1 asid-b=2 va=0x80007000 read,write,same-va`.
- **Fail-closed:** `scripts/qemu-smoke.sh` requires all nine markers. It rejects `t2t: leak`, `t2t: bad`, `t2t: probe missed` and B's sentinel on any task-A line. The `el0-leak-probe` build now also enables `t2t-leak-probe` (B's frame planted in A's root) and must report the leak and withhold `t2t: ok`.
- **Probed this session:** full `./scripts/qemu-smoke.sh` on the box (QEMU TCG): `qemu-smoke: ok`, 149 tests, including `el0_task_cannot_read_or_write_other_task`. The leak build was caught. I also ran a local negative test of the check block with five tampered logs; it failed on each one. CI run and job ids are in the PR.
- **Surprise:** QEMU TCG flushes its whole TLB on any TTBR write that changes the ASID. So the "after B, no TLBI" step only shows the kernel doesn't depend on its own TLBI here. It is not a hardware ASID-tagging or stale-TLB result.
- **Not claimed:** anything in the ADR-091 sentence (unchanged; task-vs-task stays in its non-scope). A possible revision 4 goes to the sponsor in writing later. Also not claimed: multi-core, real hardware, side channels, two loaded apps under a scheduler.
